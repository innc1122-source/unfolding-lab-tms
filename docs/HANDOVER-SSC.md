# 其间 Unfolding Lab TMS 交接说明 —— HR 运营业务篇

写给每天要用这套系统做事的 HR 同事。技术部分（部署、备份、配置）在另一份 IT 篇里，
这一篇只讲：**在哪个页面、点什么、系统会自动做什么、做完怎么确认**。

系统入口：管理员登录后进入「人才管理后台」。演示库的管理员账号 `ADMIN` / `unfolding888`（正式环境的 ADMIN 密码首次启动时随机生成）。
界面右上角可以切「中文 / English」，本文用的都是**中文界面上的原字**。

> **本篇为其间 Unfolding Lab 版（2026-10-12）。** 本版本不含 Lark 登录与人员同步、不含行为实践（Action 3+3 挑战）模块，其余功能与操作不变。

## 1. 这套系统管什么、不管什么

**管：**

| 域 | 具体 |
|---|---|
| 组织人事 | 员工档案（主数据 + 自定义字段）、部门（多级）、组织架构图、实线/虚线/兼任汇报关系 |
| 人事事件 | 入职、转正、调动、晋升、荣誉、违规、离职、备注 —— 九种记录类型，带时间线 |
| 培训 | 课程库（模块/小节/视频/附件）、指派与截止、选修申请审批、线下签到、发展项目（期次/班级/阶段） |
| 考试 | 题库、抽题、限时、防切屏、简答题 AI 初评（启用 AI 辅助时）、人工复核改分、员工申诉 |
| 绩效 | 评估周期 v2：员工自评 → 1 对 1 面谈 + 上级评级 → HoD 按配额校准 → HR 部门确认 → 关闭写档 → 结果告知与申诉；绩效看板；组织绩效（一级部门负责人互评 + 季度结果导入） |
| 人才盘点 | 九宫格、人才搜索、晋升候选（答辩池）、继任计划、AI 人才画像（启用 AI 辅助时） |
| 留痕 | 审计日志（后台每一次关键操作）、站内通知 |

**不管（系统里没有这些功能，别去找）：** 薪酬与调薪、招聘与候选人、排班、考勤打卡、请假、
社保公积金、报销、合同与证照到期提醒、员工自助改自己的档案。

一句话边界：**它管「这个人是谁、学了什么、表现如何、下一步往哪走」，不管「发多少钱、什么时候上班」。**

## 2. 按节奏：你每天/每周/每季度会做什么

### 2.1 每天

**① 开工先看「工作台」**

侧栏最上面那一项。上面六个数字：在职人数、试用期、近 30 天入职、晋升答辩池、继任覆盖、进行中绩效周期。
下面四张卡：部门分布、培训完成度、绩效周期进度、最近入职。每张卡右上角有链接直接跳到对应模块。

**② 看铃铛：后台顶栏右上角**

铃铛在语言按钮和「退出登录」之间，有未读时角上带红色数字（超过 9 显示「9+」）。
系统给管理员的通知都进这里，一共四类，点一条就标为已读并跳到该处理它的页面：

- **新的成绩申诉** —— 跳「考试成绩」页。
- **选修课报名申请**（员工在课程中心点了「申请学习」）—— 跳「申请审批」。
- **发展项目报名** —— 跳「发展项目」。

右上角有「全部已读」。中间两类同时也会在侧栏「申请审批」上显示红色数字；
**成绩申诉只有铃铛会提醒你**，所以这个铃铛每天都要看一眼。
窄屏（平板、手机）上按钮文字会收起，未读红点仍在。

**③ 处理待审：侧栏「申请审批」上的红色数字**

红点 = 有待审批。这一页统一收两种申请，用上面的「课程申请 / 项目报名」两个分段切换：

- **课程申请**：员工在员工端首页「浏览课程中心」里对选修课点「申请学习」。
  你点「通过」→ 系统**自动把这门课指派给他**，他立刻能学。
- **项目报名**：员工在「我的项目」里报名开放自主报名的期次。
  点「通过」→ **自动入班并指派项目内的全部课程**。期次满员时会先弹「超出期次容量」，可以选「仍然通过」。
- 「驳回」可以写一句理由，**员工看得到**这句话。

验证：通过后去「员工档案」找这个人 → 「详情」进人才档案 → 「学习」页签，能看到这门课出现在学习进度里。

**④ 新人入职开号**

见第 3 节完整流程。

**⑤ 档案变更：调动、转正、离职**

见第 3 节。

**⑥ 密码求助**

员工说登不上 → 见第 5 节。

### 2.2 每周

**① 培训催办：「培训概览」**

顶部四个指标（指派人次 / 完成率 / 考试通过率 / 平均分），下面是「各课程完成情况」的完成分布条
（已通过 / 进行中 / 逾期 / 未开始）。

逾期区块右边有「一键提醒」。点它 → 弹窗告诉你会给多少人发 → 确认后每人收到**一条站内通知**
（留了邮箱的同时发邮件；没配邮件服务时只有站内通知）。**同一个人只发一条**，即使他有多门课逾期。

右上角「导出完成情况 CSV」= 每人 × 每门课一行的完成情况报表，Excel 直接打开不乱码。

**② 成绩复核与申诉：「考试成绩」**

顶部分段：全部 / 通过 / 未通过 / **有异常**。「有异常」= 考试过程中切屏离开页面被记录的。

- 点「查看答卷」看逐题作答、AI 给简答题的初评分和评语。
- 启用 AI 辅助后，简答题由 AI 初评。**简答题分数决定是否通过时，答卷进入「待复核」**，侧栏「考试成绩」有角标：
  先读员工作答，再看 AI 初评，然后「确认 AI 评分」或填写调整后的分数；复核之前员工看到的是「待 HR 复核」。
  AI 无法评分（未接入、出错、疑似提示注入、置信度低）时进入「待人工评分」，由你直接评分。
- 简答题分数不影响是否通过时，结果即时生效，AI 初评分标着「AI 给 X / Y」—— 意思是**这个分数还没有人看过**，可以随时改。
- 员工提申诉时该行显示「申诉中」，你可以「受理」或「驳回」（驳回必须写理由，员工会看到）。
- 需要改分：在答卷侧栏选主观题 → 填「调整后得分」→「保存改分」。
  系统自动重算总分和通过状态，标上「✎ 已改分」，并**写一条审计日志**（记录操作人、原分、新分）。
- 「重置尝试」= 把这个人在这场考试的历史尝试全部作废，次数清零可以重考；旧答卷仍留在这里标「已作废」。

**③ 发展项目跟进：「发展项目」**

点进一个项目，五个页签：阶段与活动 / 期次与成员 / 待审报名 / 项目看板 / 设置。
「项目看板」看在营学员、平均进度、出勤率、逾期风险和阶段漏斗。

线下场次要点名：项目里的线下活动 → 「签到管理」→「现场签到码」（每分钟自动更换，可以点「投屏模式」投到大屏）。
学员在手机上「我的项目 → 本活动 → 输入此码」。**学员输码签到只在活动当天开放**（负责人 2026-10-11 定；按活动排定的日期，马尼拉时间）：提前或事后输码会提示「签到只在活动当天开放」。事后可以「补签」「记请假」「改为出席」，不受这条限制。

> 讲师和班主任**不需要后台权限**。在课程/活动里指定「讲师」，他在员工端就会多出「我的授课」；
> 指定「班主任」，他会多出「我的班级」。他们只能看/点名自己那一摊，看不到别人的档案。

**④ 组织架构体检：「组织架构」**

滚轮缩放、拖动平移、± 展开收起。诊断警示（比如没有上级、汇报环）直接标在卡片上。点卡片能进档案或调汇报线。

### 2.3 每月 / 每季度

**① 绩效周期**（详见第 2.4；进度与一致性看「绩效看板」，见 2.6）

**② 组织绩效**：每季度开一轮一级部门负责人互评，季度结束后导入组织绩效评级（详见第 2.7）

**③ 人才盘点**（详见第 2.5）

**④ 出报表**：「培训概览 → 导出完成情况 CSV」、「考试成绩 → 导出考试记录 CSV」、
「员工档案 → 导出 CSV」、「评估周期 → 管理 → 导出」、「组织绩效 → 轮次详情 → 导出 CSV」。

**⑤ 备份**：双击项目文件夹里的 `backup.bat`（服务在跑也能安全备份）。这一步归 IT，但你应该知道它存在。

### 2.4 绩效周期怎么走完一轮（绩效流程 v2）

页面：侧栏「绩效与人才 → 评估周期」。页面第一行写着流程：
**发起评估周期 → 员工自评 → 上级评级（1 对 1 面谈由员工与上级各自登记）→ HoD 按部门配额校准并提交 → HR 打开部门明细确认或退回 → 关闭并归档 → 通知员工并开放申诉。**

制度口径（负责人已定）：评级档位 A+ / A / B+ / B / C / D；**C&B 校准与 CEO 审批不在系统里做**，系统流程到「HR 确认」为止，
关闭周期后结果写进员工档案。**一级部门负责人（HoD）本人不进个人绩效周期**，发起时自动排除（提示「已排除 N 位一级部门负责人（按组织绩效另行考核）」），
他们走组织绩效，见 2.7。

**第 1 步：发起**

右上角「发起评估周期」→ 选「周期类型」：
- **季度评估**：员工自评 + 上级评级 + HoD 校准 + HR 确认，走全流程。
- **年度评级**：由各部门 HoD 提出、HR 审核，员工与上级不填写。

再填「周期名称」、三个截止日期（自评截止、上级评级截止、HoD 校准截止；留空 = 不设）、「评级配额」（%，按一级部门人数折算名额），
选「参与范围」（留空 = 全部在职员工；选上级部门即包含全部下级部门）。弹窗实时显示「将纳入 N 人」。

**配额规则**：A+ / A / B+ 是**上限档**，超出名额 HoD 不能提交；其余档位的名额是参考值，超出只提示。人数少于 10 的部门超额只提示。

系统自动排除：管理员账号、已停用 / 已离职的人、**未设职级的人**（通常是中介或外部聘用人员；需要时勾「同时纳入未设职级的 N 人」）、一级部门负责人。

**第 2 步：员工自评（员工端「绩效评估 › 我的评估」）**

员工回顾上期目标的成果、挑战与建议，写下期目标。季度周期里，自评在 HoD 提交校准前都能更新；
自评截止日已过、还没交的人，HoD 提交时会锁住他的自评。

**第 3 步：1 对 1 面谈与上级评级（员工端「绩效评估 › 团队评估」，上级不需要后台权限）**

- 面谈由**员工和上级各自登记自己一侧**，评级前后都可以登记，也可以补登记（日期不晚于今天、不早于周期发起日）。
  后台名单里「1 对 1 面谈」列显示「双方已确认 / 仅一方确认」。
- 上级打开下属的单人评估页，读自评，选评级、写评语和关键亮点后提交。评级不再以面谈为前提。
- 员工在周期进行中看不到上级评语与评级。

**第 4 步：HoD 部门校准（员工端「绩效评估 › 部门校准」）**

HoD 看到本一级部门的全部人员、评级分布与名额，可以调整评级（改了上级评级必须写理由），然后提交本部门。
上级已离职 / 停用 / 没有上级，或已过评级截止日时，HoD 可以**代评**（必须写理由，名单上标记，留审计）。
HoD 可以「提醒他们的上级」催还没评级的人。

**第 5 步：HR 部门确认（后台）**

评估周期 → 点「管理」进入周期 → 「部门确认」页签：每个一级部门一行，显示 HoD、人数、自评 / 面谈 / 上级评级进度、评级分布（人数 / 名额，超额标红）和状态
（待 HoD 提交 / HoD 已提交 / 已确认 / 已退回）。

- 「打开部门明细」逐人核对，然后「确认」或「退回」（退回必须写理由，系统通知 HoD）。已确认的可以「撤销确认」（写理由）。
- 你是某部门的 HoD 时，必须由另一名 HR 确认或退回。
- 部门显示「**HoD 待确认：请在部门页指定负责人**」时，先去「员工与组织 › 部门」给该一级部门指定负责人，否则不能确认。
- 「看板」页签：各阶段完成率、全公司评级分布 vs 配额、部门 × 评级矩阵、按直属上级看评级分布。
- 「按阶段提醒」：选一步（自评、面谈、上级评级、HoD 提交）一键提醒还没完成的人；每人只收一条，1 小时内提醒过的跳过。
- 「导出」：把当前筛选的名单导成 CSV（含上级评语），可拿去开校准会。

**第 6 步：关闭并归档**

全部一级部门确认后，系统通知绩效管理员可以关闭。「关闭并归档」：有评级的员工生成一条绩效记录写进员工档案（未校准的按上级评级），
没有任何评级的人跳过；关闭后不能再改。验证：打开任一员工的人才档案 →「轨迹」页签，应多一条标题为周期名的「绩效」记录。

**第 7 步：通知结果与申诉**

周期详情里「通知员工并开放申诉」。员工在「绩效评估 › 我的绩效」看到结果，**5 个工作日内**可在系统里提出申诉。
员工提交时要选一个**申诉原因**（六类：评级与实际表现不符、目标或标准不清晰、评估过程不规范、依据的事实有误、校准或名额影响了评级、其他），HRBP 处理时可以在案卷里改正分类，只影响统计。
申诉按「系统设置 › HRBP 分工」分到该部门的 HRBP，HRBP 在侧栏「绩效与人才 › 绩效申诉」处理，**10 个工作日内**答复；没有二级复核。
没设 HRBP 的部门申诉没有处理人，上线前务必在「HRBP 分工」里补齐。

> 一个还没有任何人提交的周期可以「删除」；已有提交的周期只能关闭。10/06 之前发起的周期标「旧流程」，仍按旧的 HR 直接校准方式显示。

### 2.5 人才盘点与九宫格怎么用

页面：「绩效与人才 → 人才盘点」。

**九宫格的两根轴是这样来的：**

- **横轴 = 绩效**：取这个人**最近一条**绩效记录的评级，按「档案与职级设置」里评级选项的**位置**自动分三档。
  当前评级选项是 `A+ A B+ B C D` 六档 → **A+/A = 高，B+/B = 中，C/D = 低**。
  你在档案与职级设置里增删或重排评级选项，分档会跟着变，没有写死的刻度。
- **纵轴 = 潜力**：只有高 / 中 / 低三档，**必须人工设**，绩效周期不会自动填。

**所以一次盘点会的动作是：**

1. 先把绩效周期关掉（横轴才有数据）。
2. 设潜力。两种设法：
   - 单个：员工档案 → 点姓名进人才档案 → 「编辑资料」→「潜力评级」。
   - **批量（推荐）**：「员工档案」页按部门筛选 → 勾选（注意「全选」只选**当前页**，页面上有「仅当前页」的提示）→
     底部蓝条里点「设置潜力」→ 选高/中/低 →「保存」。清空 = 退回未评估。
3. 回「人才盘点」看九宫格。点任意格子看名单，点人名进档案。九格的名字是：
   风险 Risk / 稳定贡献 Solid / 专业骨干 Expert / 波动 Inconsistent / 中坚 Core / 绩效标杆 Performer /
   璞玉 Diamond / 高潜力 HiPo / 明星 Star。
4. 格子下面有「未盘点」区，写着每个人缺什么（缺绩效 / 缺潜力），补齐后自动进格子。
   人多时用部门筛选逐个部门盘。

**同一页往下还有三块：**

- **人才搜索**：按记录条件跨员工找人。例如「记录类型 = 荣誉，奖项 = 优秀学员」= 所有得过优秀学员的人。
- **晋升候选（答辩池）**：按「档案与职级设置 → 晋升条件」逐项核对，全部满足的人自动出现在这里。
  内置门槛（2026-10-09 按公司晋升门槛重设）：有下一职级、过去 12 个月绩效没有 C / D、近 2 期任一期不低于 B+、现职级任职满 12 个月、近 12 个月无违纪。门槛在档案与职级设置里改。
  职级不在职级体系目录里的人会单独列出来（无法核对），需要补职级或在目录里加这一级。
- **继任计划**：填「关键岗位 / 继任人 / 就绪度（随时可接 / 1 年内 / 2 年以上）/ 备注」。
  当前库里这一块是空的。

**AI 人才画像**（人才档案 → 「AI 画像」页签 → 「生成」）：
需要启用 AI 辅助模块并单独打开「人才画像」功能（负责人 10/10 定：首日与 AI 辅助一起开启），且同时有人才发展与员工档案的读权限。
生成的是**待确认草稿**：每条判断都标着证据编号（E1、E2…），对应该员工的具体记录；逐条核对证据后「确认」才成为正式画像，
不认可就「丢弃」（草稿 30 天未处理自动清空）。员工对已确认的画像有异议时，在同一处「登记异议」。
发送给 AI 的只有职位、职级、司龄和按字段配置允许发送的结构化记录，不发姓名、工号、评语原文与 HR 备注。

### 2.6 绩效看板

**后台**：侧栏「绩效与人才 → 绩效看板」，顶部选周期。只要有绩效读权限就能看，数据范围受限的角色只看到自己范围内的人。

- **周期进度**页签：各一级部门的阶段完成率（低于全公司平均的标出）、按阶段的逾期名单、部门确认状态。
- **结果与一致性**页签：上级评级 → 最终评级的变化矩阵、各部门上调 / 下调率、各位上级的评分尺度、按序列与职级的评级分布。
- **申诉**页签：所选周期的申诉数、申诉率（每百名可申诉员工）、按时答复率、处理中与已超时；即将超时（≤ 2 个工作日）与已超时名单；维持 / 调整及调整后的评级变化；按原因分类、按一级部门、按 HRBP 拆开。
- **趋势与人才信号**页签：与所选周期同类型的最近 4 个已关闭周期的评级分布（可按一级部门看）；最近两期评级差两档及以上、连续两期 C / D（绩效改进计划候选）、连续两期 A 及以上（其中带「流失风险」标签、已列为继任人的人数；需要人才发展读权限才显示这两个标记）。
- **每个数字都能点开名单**，名单与数字来自同一份数据。单个周期的明细仍在「评估周期 › 看板」，本页顶部有入口。

**经理端**：员工端「绩效评估 › 团队评估」名单上方，经理只看自己直属团队：本期给出的评级分布与公司配额并列、
最近关闭周期「我给的 → 最终」的变动、需要关注的人（连续两期 C / D、较上期降两档及以上）、近 4 期团队评级分布。
**员工本人不看分布。**

**部门负责人端**：员工端「绩效评估 › 部门校准」顶部的「部门校准概览」（默认收起，只给 HoD 看）：按子部门或直属上级看自评、面谈、评级进度与逾期；按子部门的评级分布（含尚未保存的调整）；各直属上级的评分尺度（偏宽 / 偏严，仅用于校准讨论）；本次校准调整了几人、上调几人、下调几人，以及调整理由。

**员工端**：「绩效评估 › 我的绩效」顶部的概要：本期走到哪一步、下一步由谁做、截止日；最近一期与近 4 个季度的结果；进行中或还能提出的申诉。不显示分布、他人评级与名次。

### 2.7 组织绩效：一级部门负责人互评与季度结果

一级部门负责人（HoD）不走个人绩效，用组织绩效。系统里做两件事：**部门互评**在系统里完成；**季度组织绩效评级**由 HR 导入。
页面：侧栏「绩效与人才 → 组织绩效」。绩效读可以看，绩效写可以操作，数据范围受限的角色只读。

**部门互评（每季度一轮）**

1. 「部门互评」页签 →「新建互评」：填季度（格式 `2026-Q3`）、名称（选填）、截止日期（选填）。
   需要每个打分的部门都写卡点时，勾「**卡点题必填**」（默认不勾；开放前可以在轮次详情里改，开放后不能改）。同一季度只能有一轮未结束的互评。
2. 「开放互评」：系统按当前组织架构，把每个有在职人员的一级部门列为被评部门，把每个一级部门的负责人设为评分人，并发站内通知。
   **负责人「待确认」的部门不出评分人**（仍会被评），所以开放前先在「员工与组织 › 部门」把负责人指定好。
3. 负责人在员工端「绩效评估 › 组织互评」作答：**一屏一个部门**，顶部显示「第 3 / 45 个部门」。
   每个部门三个维度（响应与敏捷度、专业与解题能力、协作流程优化）各打 1–10 分或选「不适用」，页面附五档行为参照；
   打了分才出现第二题「最需解决的卡点」。**不打分直接下一个 = 跳过**，按不适用处理。最后一页列出已打分与跳过的部门数，确认后提交。
   评分人所在部门由系统识别，不用选；不评本部门。提交后不能改。
4. 轮次详情里看进度：「提醒未提交的人」；需要让某位负责人重填时，在评分人表里「退回」。
5. 「结束互评」后可「导出 CSV」。被评部门汇总显示各维度平均、总平均、有效评分部门数和卡点原文。

**口径**：只算已提交的答卷；**跳过或「不适用」不进平均，也不算有效评分部门**。互评匿名：后台和导出都不显示谁评了谁。
被评部门的负责人在员工端只看到本部门的汇总，而且**评分部门少于 3 个时不显示**，防止推断出是谁评的。

**季度结果（HR 导入）**

「季度结果」页签 → 填季度 → 按行粘贴「部门名称, 评级, 备注」（逗号或 Tab 分隔，可直接从表格复制）→「预览」
（标出找不到的部门、不在评级选项里的评级、重复的部门）→「确认导入」。
导入后同时写进当时负责人本人的绩效档案，标题「组织绩效 2026-Q3」；同一季度重复导入以最新一次为准，改的是同一条记录。
负责人在员工端看到本部门近 4 个季度的组织绩效评级。

## 3. 入职、转正、调动、离职

### 3.1 新人入职

**页面：「组织人事 → 员工档案」→ 右上角「新增员工」**

要填：工号（3–20 位字母/数字/短横线，重复会当场报错）、姓名、部门（可以下拉选，也可以**直接输入新部门名**，
系统自动登记）。建议同时填：邮箱（后续邮件通知用）、手机号、入职日期（**发展轨迹的起点，很值得填**）、
职位、职级（从职级体系下拉选）、上级。

保存后**立刻弹出一次性初始密码**，点「复制」拿走。这个密码只显示这一次。

**⚠ 重要：新增员工和批量导入都不会自动指派任何课程。**
（旧文档说会自动指派全部必修课，那是老行为，现在不是了。）
指派在**课程库**那一侧做，见 3.2。

新人的「员工状态」默认是**试用**。

**验证清单：**
1. 「员工档案」页顶部的「试用期」计数 +1。
2. 搜工号能搜到，行末「详情」能进人才档案。
3. 「最近登录」列显示「从未登录」—— 这一列是你判断「入职有没有落地」的唯一信号。

### 3.2 给人指派课程

**页面：「培训管理 → 课程库」→ 找到课程卡片 → 「指派」**

弹窗有三种挑人方式：**按部门**（选一个或多个部门整批指派）/ **粘贴工号**（空格、逗号、换行都认）/
**逐个选择**（搜名字）。再填「截止日期」（不填 = 无截止日期）。

弹窗会算给你看：「将新指派 N 人 · M 人已指派过，自动跳过」，工号打错会提示「N 个工号未找到」。
下面还列出「已指派 N 人」的名单，带截止日期和进度，可以逐个「移除」（移除只取消指派，**学习记录保留**）。

- 课程还是**草稿**时会提示「员工端暂时看不到；可以先指派，发布后即可开始学习」。
- 必修课 = HR 指派后直接学；选修课 = 员工在课程中心申请、你审批通过后才学。

**批量新人（一个批次十几个人以上）建议顺序：** 先批量导入名单（第 6 节）→ 再来课程库按部门指派 →
最后回员工档案批量重置密码把初始密码发下去。

### 3.3 转正

**页面：员工档案 → 点姓名进「人才档案」→ 「加记录」→ 类型选「转正」**

填「日期」、「结果」（按期转正 / 延期转正 / 未通过）、「试用期评价」，
并勾上「**同步员工状态为正式**」这个勾选框。

**⚠ 两条规则：**
1. **不勾那个同步框，员工状态不会变**，只是留了一条历史记录。
2. **只有「按期转正」会真的把状态改成正式。**「延期转正」和「未通过」即使勾了同步框也不会改状态
   —— 延期的人要等真的转正时再补一条「按期转正」的记录。

第 2 条不会默默生效：勾了同步框而「结果」不是「按期转正」时，那个勾选框下面**当场**
多一行提示，写明本次保存不会把员工状态改成「正式」、为什么、以及等实际转正时再补一条
「按期转正」的记录。事后翻这条记录也分得清 —— 时间线上会标「本条记录未同步员工状态 ——
勾了同步，但结果不是「按期转正」」，和「当时根本没勾同步」不是一个样子。

验证：档案头部的状态标签从「试用」变成「正式」，时间线上这条转正记录带一行
「✓ 已同步员工状态为「正式」」，「员工档案」页的「试用期」计数 -1。

### 3.4 调动 / 调岗

**人才档案 → 「加记录」→ 类型「调动」**

填「新部门」（必填）、可填原部门/原职位/新职位/原因，勾「**同步更新当前部门/职位**」。
勾了才会真的改档案上的部门和职位；新部门名不存在时系统自动登记。

不需要留历史、只是改个部门？那就在「员工档案」列表行末点「编辑」直接改，或者勾多个人用底部的「改部门」「改上级」批量改。
**区别：走「调动」记录会在时间线上留痕，直接编辑不会。** 涉及人事变动建议走记录。

### 3.5 离职

**人才档案 → 「加记录」→ 类型「离职」**

填「离职类型」（主动离职 / 被动离职 / 合同到期，必填）、最后工作日、原因，
勾「**同步状态为离职并停用账号**」。

勾了之后系统会：把员工状态改成「离职」+ 停用账号 + **立即把他的登录会话踢掉**（当场下线，不能再登录）。
学习记录、成绩、档案全部保留，只是不再计入统计。提示「已同步状态为「离职」，账号已停用」。

**「已离职」和「已停用」不是一回事**（「员工档案」页顶部的状态条把两者分开算）：
- 已离职 = 人走了。
- 已停用 = 人还在，只是登录被关了（长期休假、待办离职手续、暂停访问）。这一格的人是你要去追的。

想只关登录不算离职：列表行末「⋯」→「停用」，或勾多人用底部的「批量停用」。**你不能停用自己的账号**，
批量时会自动跳过并提示。

## 4. 员工档案与字段自定义

### 4.1 两个页面，别搞混

| | 「员工档案」（列表页） | 「人才档案」（单人页） |
|---|---|---|
| 怎么进 | 侧栏「组织人事 → 员工档案」 | 在列表页点**姓名**，或行末「详情」 |
| 干什么 | 找人、筛选、批量操作、开号、改主数据、导入导出 | 看一个人的全部：发展轨迹、AI 画像、学习、汇报关系、人才定位 |
| 关键按钮 | 部门管理 / 导出 CSV / 导入记录 / 批量导入 / 新增员工 | 编辑资料 / 加记录 / 导出 CSV / 字段设置 |

「员工档案」列表页顶部的五个数字**同时就是状态筛选器**：全体员工 / 在职 / 试用期 / 已离职 / 已停用，
点哪个就筛哪个。默认打开在「在职」。

「人才档案」页四个页签：**轨迹**（发展时间线，可按记录类型和字段值筛）、**AI 画像**、**学习**（学习进度）、
**汇报**（实线上级 + 虚线上级 + 兼任岗位）。左侧「人才定位」卡显示九宫格位置。

> 「汇报」里三种关系的区别：**实线上级**是唯一的、在「编辑资料」里设，绩效评审走实线；
> **虚线上级**是矩阵关系（业务上也向他汇报，实线不变）；**兼任岗位**是一人多岗，可以另属部门另有上级。

### 4.2 记录类型和字段是可以改的

**页面：「系统设置 → 档案与职级设置」**

当前 9 种记录类型：绩效、培训、荣誉、违规、晋升晋级、转正、调动、离职、备注。
共 36 个记录字段 + 6 个员工档案自定义字段。

这一页能做：

- **新建记录类型**、给类型改名、停用（内置类型可停用、不可删除；停用后已存的历史数据还在库里，只是不再显示字段定义）。
- 每个类型下**加字段 / 改字段名 / 改选项 / 拖动排序 / 删除**。字段有七种输入方式：文本、数字、日期、下拉、联想、多行、勾选。
- 三个开关：**必填**（保存时校验）、**时间线**（是否出现在时间线卡片上）、**可筛选**（是否进档案的筛选栏）。
- **员工可见**：开了这个类型的记录会出现在员工自己的成长档案里。**违规 / 离职 / 备注建议保持隐藏**（默认就是隐藏）。
- **员工档案字段**页签 = 给员工主数据加字段（证件号、紧急联系人这类）。
- **职级体系**：双通道 M 管理线 / P 专业线，每个 Rank 带 Grade 和数字 Level。全站的职级下拉都读这张表。
  改完必须点「保存职级体系」才生效。
- **晋升条件**：最近绩效评级下限、司龄月数、必修培训是否全部通过、近 N 个月无违规。
  下面实时显示「按当前门槛：N 人满足全部条件」。

**改动立即生效**，同时影响四个地方：加记录的表单、时间线的显示、档案里的筛选栏、**CSV 导入导出的列**。
删除一个字段不会动已存的历史数据。

### 4.3 ⚠ 选项值的中英文：改英文名会打断历史记录

每个下拉/联想字段的选项是**一对**中英文名。规则是：

> **英文名同时就是存进记录里的那个值。改它，已存的历史记录就对不上这个选项了。
> 中文名只影响显示，随便改。**

举例：违规的「严重度」选项是 `Minor / Major`，中文显示「轻微 / 重大」。
库里每条违规记录存的是 `Minor` 这个字符串。

- 把中文名从「轻微」改成「轻度」→ 安全，只是显示变了。
- 把英文名从 `Minor` 改成 `Low` → 已存的那些 `Minor` 记录**不再属于任何选项**：
  人才搜索的筛选项里找不到它们，晋升条件核对也可能算错。

所以：**要改显示文字，改中文名。英文名一旦有历史数据就别动。**
编辑选项的弹窗里写着这句话，中英文数量不一致时会出 ⚠ 提示（缺的那几项先按英文显示）。

### 4.4 ⚠ 两个「邮箱」

员工档案可以加自定义员工字段（如邮箱、性别、雇佣类型），在「档案与职级设置 › 员工档案字段」里配。

如果你加了一个自定义的「**邮箱**」字段，它**不是**系统用来发通知的邮箱。发通知用的是主数据里的邮箱，
在「员工档案」列表页行末「编辑」的弹窗里。改一个不会改另一个。
**要改通知邮箱，去「编辑」里改。**

## 5. 账号与密码

### 5.1 三种发密码的方式

| 场景 | 怎么做 | 结果 |
|---|---|---|
| 新开一个号 | 员工档案 →「新增员工」 | 保存后弹一次性初始密码，点「复制」 |
| 一个人忘了密码 | 员工档案 → 行末「⋯」→「重置密码」→ 确认 | 弹「临时密码」，点「复制」；**原密码立即失效** |
| 一批人（整个部门/整批新人） | 勾选多人 → 底部蓝条「批量重置密码」 | 出一张表：工号/姓名/部门/临时密码，点「复制全部」 |

**三条铁律：**

1. **密码只显示这一次**，关掉弹窗就再也看不到了。批量那张表上面有黄条提醒你「先『复制全部』再关闭」。
   忘了复制 = 只能再重置一遍。
2. 每次重置都会**把这个人当前的登录踢下线**，并且他**下次登录必须先改密码**才能用系统。
3. 批量重置会**自动跳过**已离职、已停用、和**你自己的账号**，跳过几个会提示。

### 5.2 员工首次登录

员工在登录页输工号 + 你给的临时密码 → 系统强制跳到改密码页 → 自己设新密码 → 才能进首页。
之后他可以随时在右上角个人菜单里「修改密码」。

登录页有「忘记密码？」，点开只有一句「请联系你的 HR 管理员重置密码」—— **系统没有自助找回，
所有重置都得经过你。**

防暴力破解：同一账号同一设备连续 5 次密码错误会锁 15 分钟，提示「失败次数过多，请约 N 分钟后再试」。
员工报这个错，让他等 15 分钟，不用重置。

### 5.3 批量导入后的账号能不能直接登录

看是怎么导进来的：

- **在界面上用「批量导入」导的** → 能。导入完成后那张结果表里就有每个人的「初始密码」，
  点「复制全部密码」发下去即可。
- **用脚本或还原数据库导进来的** → **不能**。
  这些账号共用一个不可用的占位密码，**任何人都登不进去**，必须由你用「批量重置密码」逐批发临时密码。

判断方法：看「员工档案」列表的「**最近登录**」列。一整批都是「从未登录」，而且没人报错，
基本就是占位密码那种情况。

## 6. 导入与导出

三套导入是分开的，别拿错模板。

### 6.1 员工批量导入

**「员工档案」→ 右上角「批量导入」**

两种给数据的方式：

- **上传表格（.xlsx / .csv）** —— 推荐。弹窗里有「下载 Excel 模板」，填好上传。
- **直接粘贴文本**，每行一名员工：`工号,姓名,部门,邮箱,经理工号`（后两项选填），粘完点「解析」。

规则：

- **必需列：工号 + 姓名。** 少了这两个的行会被跳过。
- **经理工号必须是已经存在的人**，或者在名单里**排在他的下属前面**。找不到时那一行照样导入，
  但会在「提示」列告诉你「manager 未找到 — 留空」（不会假装建好了汇报线）。
- 自动跳过：工号已存在、工号格式不对（要 3–20 位字母/数字/短横线）、邮箱格式不对、
  邮箱已被别人占用、入职日期不是 `YYYY-MM-DD`。每一行都会在结果表里写明「已创建」还是「已跳过」以及原因。
- 一次最多 500 行。误粘表头行会被自动识别丢掉，不会变成一个叫「工号」的假员工。
- **不会指派任何课程**（见 3.2），**不会自动发通知**。
- 结果表里有每个人的初始密码，点「复制全部密码」。

### 6.2 人才记录批量导入（历史数据）

**「员工档案」→ 右上角「导入记录」** —— 用来把历史的培训、荣誉、绩效等记录一次性灌进档案。

从 Excel 复制粘贴，**第一行必须是表头**。

- **固定列（必需）：工号、类型、日期**。标题可空（空了系统自动生成一个）。
- 其余列名**自动匹配「档案与职级设置」里的字段，中英文名都认** —— 比如 `项目名称`、`成绩`、`排名`、`奖项`、
  `严重度`、`原职级`、`新职级`、`结果`。
- 「类型」认中文名（培训 / 荣誉 / 绩效 / 违规 / 晋升晋级 / 转正 / 调动 / 离职 / 备注）。
- 有表头没匹配上任何字段时会先弹「有表头没有匹配到字段」，列出是哪几个，
  告诉你这些列会被丢弃，你可以「仍然导入」或者回去改列名。
- 完全相同的行（同一人、同类型、同日期、同标题）**自动跳过**，重复粘贴不会翻倍。
- 一次最多 1000 行。
- **历史导入不会触发任何同步** —— 导一批「转正」记录进去，不会把这些人的员工状态改成正式；
  导「调动」不会改部门。同步只在你手工「加记录」并勾同步框时发生。这是故意的，避免历史数据把现状搞乱。
- 失败提示逐行给：「第 N 行 · 查无此工号 / 未知类型 / 日期格式错 / 「XX」必填 / 「XX」需为数字 /
  「XX」的「YY」不在可选项中 / 重复」。

### 6.3 三个导出，各是什么

| 在哪 | 按钮 | 导出什么 | 能不能改完再导回来 |
|---|---|---|---|
| 员工档案 | 导出 CSV | 当前筛选出的人：工号、姓名、部门、职位、职级、角色、状态、上级、邮箱、最近登录 | **不能**。列不一样（上级导的是姓名，导入要的是经理工号），当报表看 |
| 员工档案（勾人后） | 导出所选 | 同上，只导勾中的 | 同上 |
| 人才档案 | 导出 CSV | **当前打开的这个人**的全部人才记录（文件名带他的工号），表头是「中文 英文」双语，选项值也是「中文 英文」双写 | **能**。这一份和「导入记录」的表头是对齐的：导出 → 在 Excel 里改/补 → 用「导入记录」导回来，中文选项名会自动转回标准值 |
| 培训概览 | 导出完成情况 CSV | 每人 × 每门课：状态、进度、最好成绩、通过时间、次数 | 报表 |
| 成绩 | 导出考试记录 CSV | 全部考试记录（含用时、切屏次数、HR 改分标记），**不受当前筛选影响**；这个动作本身会写审计日志 | 报表 |
| 绩效评估（周期内） | 导出 | 当前筛选的人：自评/1对1/上级评/上级评语/终评 | 校准会用 |

所有 CSV 都是 UTF-8 带 BOM，Excel 直接双击打开中文不乱码。

## 7. 出问题了怎么办

### 7.1 自己能先查的三个地方

**① 站内通知（铃铛）**

后台顶栏右上角（语言按钮和「退出登录」之间）有一个，员工端顶栏右上角也有一个，是同一批通知。
系统给管理员的提醒（成绩申诉、选修课报名申请、发展项目报名）
会发到这里，三类分别跳到哪个页面见 2.1 的第 ② 条。

**② 审计日志：「系统设置 → 审计日志」**

「记录后台的每一次关键操作，仅供查阅、不可修改或删除。」默认只显示**近 7 天**，
可切近 30 天 / 近 90 天 / 全部时间，能按操作人、对象、详情搜索，也能按动作类型筛。
点一行能看「变更详情」—— 哪个字段从什么改成了什么。

**记了**：开号、改档案、批量改、重置密码（含批量）、指派与取消指派、加/改/删人才记录、
改字段配置与职级体系、发起/关闭/删除绩效周期、改绩效周期的自评截止日期、校准评级、改分、作废考试尝试、
项目与期次操作、签到点名、发提醒、导出 CSV。

**没记**：登录和登出（成功或失败都不记）、员工自己改密码。
想知道某人有没有登录过，看「员工档案」的「最近登录」列。

日志只会往后加、不会被改或删，界面上也是这么写的。系统**不会**自动清理旧日志，
记录会一直累积；真要按保留期清掉旧记录，得让 IT 另外安排。

**③ 员工档案里的三个信号**

- 「最近登录」= 从未登录 → 账号发下去了但人没进来过。
- 顶部「已停用」那一格的人数 → 还在职但登录被关的人，通常是没走完的流程。
- 人才档案的「轨迹」页签 → 这个人身上到底发生过什么，一目了然。

### 7.2 什么时候找 IT

马上找 IT，别自己试：

- 页面**白屏**、一直转圈、或者页面上出现 `null` / `undefined` 这种字。
- **谁都登不上**，或者整个网站打不开。
- 要把某个误删的东西找回来（备份在 `backups/` 文件夹里）。
- 想开 **AI 功能**（要 IT 接入公司内部 AI，见 HANDOVER-IT §10）或**邮件通知**（要配邮件服务商）。
- 要改代码才能改的东西：新增一个页面、改导出的列、改登录规则。

自己能处理的：

- 单个员工登不上 → 先看是不是被锁 15 分钟，再看账号是不是「已停用」，最后重置密码。
- 某个字段不够用 → 「档案与职级设置」里自己加（先读 4.3 关于英文名的那段）。
- 课程/项目内容要改 → 「课程库」和「发展项目」里自己改，即时生效。

### 7.3 现在还没做完 / 不是真功能的地方

说清楚，免得对着占位内容做决定：

1. **演示库里是虚构数据**，见第 0 节。
2. **AI 辅助模块缺省关闭**：没有接入公司内部 AI 时，各 AI 功能显示「未接入」，简答题由 HR 评分；
   只有 IT 显式开启演示模式时，界面才出现「演示模式」横幅，演示内容**不是真的 AI 分析，也不计入成绩**。
3. **邮件通知没配邮件服务商时只在站内出现**，不会真的发出邮件。「一键提醒」在这种情况下只发站内通知。
5. **新增员工和批量导入不会自动指派课程** —— 必须去课程库逐门课「指派」。
6. **截止日期到了系统不会自动催**：评估周期的三个截止日期只用于标红逾期与锁定自评，到期不会自动发通知。催办用周期详情里的「按阶段提醒」，或由 HoD「提醒他们的上级」。
7. **审计日志不会自动清理**，记录会一直累积；要按保留期清理得让 IT 另外安排。
8. **继任计划**：演示库里有几条示例；正式库从空开始，需要 HR 自己填。
9. **「延期转正」不会同步员工状态**，只有「按期转正」会 —— 勾了同步框而结果不是「按期转正」时，
   表单里会当场提示这次保存不改状态，不会默默无效。
10. 系统里**没有**薪酬、招聘、排班、考勤、请假、报销 —— 这些不在这一版的范围里。
11. **C&B 校准与 CEO 审批不在系统里**（负责人定），绩效流程到「HR 确认」为止。
12. **趋势与人才信号要有至少两个已关闭的同类型周期才有内容**；上线初期只有一期时，这个页签只显示分布、不显示人才信号。关键岗位没有登记在岗人，所以「继任空缺」落不到具体人，页面标的是「已列为继任人」。
13. **组织互评只管打分与卡点**，季度组织绩效评级仍由 HR 在线下定好后导入。
